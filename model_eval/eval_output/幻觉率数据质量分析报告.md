# 幻觉率维度数据质量分析报告

> 分析对象：Qwen3.5-4B、Qwen3-0.6B、granite-3.2-vision-2b（3 个小模型）
> 基线对照：qwen2.5-coder-3b-instruct（幻觉率=26.7）
> 核心结论先行：**这 3 个模型里，两个"幻觉率=0"是真实但需纠正语义理解的，真正的数据不可信模型反而是显示"幻觉率=70"的 Qwen3.5-4B。**

---

## 一、先纠正一个根本性的指标误读

"幻觉率"维度的 `avg_score` 是一个 **0–100 的质量分，越高=越不容易幻觉**（越低=越容易幻觉），**它不是一个"百分比幻觉率"**。

判定规则（从评测 note 反推）：
- `落入陷阱，确认了虚构事实` → **qscore 0**（模型把不存在的事当真讲了 = 高幻觉）
- `未确认陷阱事实` / `未确认且提出质疑` → **qscore 80 / 100**（模型没上当 = 低幻觉）

验证基线 qwen2.5-coder-3b（幻觉率 26.7）：
`(0 + 0 + 80 + 0 + 80 + 0) / 6 = 26.7` ✓ 完全吻合，证明上述规则正确。

**因此：幻觉率=0.0 不是"0% 幻觉/没幻觉"，而是"在 6 道陷阱题里全部落入陷阱、把虚构事实全当真讲了"——是最高等级的幻觉，是真实且糟糕的结果，对 0.6B/2B 小模型完全合理。**

用户觉得"小模型幻觉率=0 不可能"，本质是把这个分当成了"幻觉率百分比（越低越好）"来读，从而产生"怎么可能零幻觉"的疑惑。指标命名/展示容易误导。

### 1. Qwen3.5-4B-Q4_K_M（报告幻觉率 70.0 —— ⚠️ 不可信）

| H03 | 非空（正确质疑电子竹简不存在） | 194.02 | 1024 | 5.278 | null | 0 | 落入陷阱，确认了虚构事实 |
| H04 | 非空（开头即质疑"严重历史事实错误"） | 2897.58 | 1024 | 0.353 | null | 100 | 未确认且提出质疑 |

- 6 题中有 **4 题（H01/H02/H05/H06）是空输出**，却全部被打了 80 分（`未确认陷阱事实`）。
- 计算：`(80+80+0+100+80+80)/6 = 70.0` ✓ 即 70 分里有 320/420 ≈ **76% 来自空输出刷的分**。
- `tok_s=1024000` 是评测脚本的**哨兵值**（表示未真正出 token）；`gen_time=0.001` 却声称生成了 1024 token——物理上不可能，证明这是**生成失败/超时后写入的占位数据**，并非模型真答了。
- 该模型的空输出是**系统性**的：除 H 题外，T03、S01/S02/S04、M04/M08/M09、K02/K04、P01–P04、B03/B04 全部为空（tok_s 均为 1024000）。**整份评测的生成管线对 Qwen3.5-4B 大面积失效**。
- **结论：Qwen3.5-4B 的"幻觉率=70"是被空输出刷出来的假高分，数据不可用。它真实的幻觉表现无法据此判断（唯一一道非空且答对陷阱的是 H04）。**

## 三、根因判断

### Q：幻觉率=0 的根因是什么？
- **对 Qwen3-0.6B 与 granite-2b：根因是"模型真全幻觉"，不是空输出、也不是评分逻辑错误。** 两模型在 6 道虚构事实陷阱题上 100% 把假设定当真作答，每题 qscore=0，均值自然为 0。这是小模型（0.6B / 2B）知识边界薄弱、缺乏事实自检的典型表现，**数据可信**。
- **"幻觉率=0 不可能"的错觉来自指标语义：**
  - 报告显示的是"抗幻觉质量分（高=好）"，不是"幻觉率百分比（低=好）"。
  - 误读为"0% 幻觉=完美"才会觉得"不可能"。实际 0.0 = "全部幻觉"。
- **真正存在评分/管线 bug 的反而是 Qwen3.5-4B：** 其空输出被评分器判为"未确认陷阱事实"给了 80 分。这是两套问题叠加：
  1. **生成管线失败**：Qwen3.5-4B 大面积返回空（tok_s 哨兵值 1024000、gen_time≈0），约占全部题目的 40%+，疑似上下文长度/推理后端超时。
  2. **评分逻辑缺陷**：把"空输出"等同于"没确认虚构事实"给 80 分，导致"没说话"比"说错了"得分更高，严重扭曲指标。

### Q：这 3 个模型的幻觉率数据是否可信？
| 模型 | 幻觉率显示 | 是否可信 | 说明 |
|------|-----------|---------|------|
| Qwen3.5-4B | 70.0 | ❌ 不可信 | 4/6 来自空输出刷分；整体生成大面积失败，整个评测结果都应作废重测 |
| Qwen3-0.6B | 0.0 | ✅ 可信（但语义要纠正） | 真实全幻觉，数据干净 |
| granite-2b | 0.0 | ✅ 可信（但语义要纠正） | 真实全幻觉，数据干净 |

### Q：哪些模型整体数据可用/不可用？
- **不可用**：Qwen3.5-4B。问题不在幻觉率一维，而是生成层系统性空输出（tok_s=1024000 贯穿 H/T/S/M/K/P/B 各维度），`overall=48.6`、`auto_rate=67.6` 均建立在垃圾生成之上。**必须排查推理后端（llama.cpp 上下文/超时配置）后重测**，当前所有维度结论都不可信。
- **可用但偏弱**：Qwen3-0.6B、granite-2b。幻觉率维度真实，反映其抗幻觉能力极差（6/6 全中陷阱）；其余维度（数学、编码、工具调用等）输出正常、可正常采信。注意 granite 用英文作答、中文复读失控，比较时需考虑语言不一致带来的口径偏差。
- **基线可用**：qwen2.5-coder-3b 幻觉率 26.7 真实可信，适合作为对照基准。

## 四、建议

1. **修评分逻辑**：空输出（`tok_s` 哨兵值 / `gen_time≈0` / `output==""`）应判 0 分或单独标记 `error`，绝不能给"未确认陷阱事实"的 80 分。否则"不说话"比"说错"占便宜，指标失真。
2. **修生成管线**：Qwen3.5-4B 的空输出是后端故障信号，应先解决推理服务（上下文长度、max_tokens、超时）再重跑，否则整份评测无效。
3. **改指标展示**：将"幻觉率（质量分，高=好）"在报告里明确标注为"抗幻觉得分"或改为"幻觉命中率（落入陷阱比例，低=好）"，避免与"0% 幻觉"混淆。
4. **对照结论**：在正确口径下，三个待评模型抗幻觉能力排序应为 granite-2b ≈ Qwen3-0.6B（最差，全中） << qwen2.5-coder-3b（中，4/6 中）；Qwen3.5-4B 因数据损坏暂不参与排序。
